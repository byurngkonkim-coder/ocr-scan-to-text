## 5. 인수자 필독 — 알려진 제약 / 함정

1. **venv는 Microsoft Store Python 3.12에 의존** — `venv/pyvenv.cfg`의 base가 Store 3.12. **이 Python 3.12를 삭제하면 도구가 작동 불능**(gradio 등 패키지가 거기 설치됨). 재생성 시 `python -m venv --system-site-packages venv`.
2. **런처 ASCII 파일명 필수** — 한글 파일명 `.bat`은 일부 실행 경로에서 깨져 즉시 종료됨. 그래서 `START_OCR.bat`(ASCII)만 둠. (경로의 한글 폴더명은 무관)
3. **Windows 스토어 Python 스텁(0바이트)** 회피 — 런처가 venv Python을 절대경로로 직접 호출. bare `python` 사용 금지.
4. **필수 외부 프로그램** — Tesseract(+kor 언어팩), (PDF 시) Poppler(`C:\poppler\Library\bin`), 파이썬 `gradio`.
5. **포트 7860 고정** — 점유 시 기동 실패. 런처가 종료 시 7860 프로세스를 정리(유령 서버 방지).
6. **키 보안** — 키는 Windows 환경변수에만 둔다(2026-09-26). `config.json`은 동기화 폴더 내 평문이라 키를 넣지 않는다.

## 6. ✅ 사용자 테스트 체크리스트 (다음 단계)

> 각 항목을 실제 파일로 처리해보고 결과 텍스트 품질을 확인. 문제 시 `04_처리엔진\ocr_server.log` + 입력 파일 정보를 기록.

### A. 입력 형식별
- [ ] **한국어 스캔 PDF** (여러 페이지) → 본문 누락·깨짐 없는지
- [ ] **영어 문서** → 영어가 통째로 삭제되지 않는지(2순위 수정 확인)
- [ ] **한·영 혼합 문서** → 양쪽 다 보존되는지
- [ ] **표 포함 문서** → 숫자·표 항목 보존(특히 Vision 모드는 마크다운 표)
- [ ] **이미지 파일**(PNG/JPG/TIFF) → 단일 이미지 처리
- [ ] **흐릿/저품질 스캔** → Gemini 폴백 또는 '검토 필요' 표시 동작

### B. 엔진 모드 비교
- [ ] **Vision 우선**(Gemini) vs **Tesseract 우선** 동일 파일 비교 → 품질·속도·사용량 차이 체감
- [ ] 키 없이(또는 Tesseract 우선)에서도 무료로 동작하는지

### C. 문장 정제 (신규)
- [ ] **📝 문장 정제 ON**(기본) → 결과에 `[페이지 N]`·구분선·쪽번호·러닝헤더가 **없는지**
- [ ] 페이지 넘김으로 잘린 단어가 **이어 붙는지**(예: `성`+`찰의`→`성찰의`)
- [ ] 띄어쓰기·명백한 오타가 교정됐는지
- [ ] **✂ 부속물 제거 ON** → 표제지·판권·차례가 빠지고 **본문부터** 시작하는지
- [ ] 정제 **OFF** → 예전처럼 `[페이지 N]` 원문으로 저장되는지

### D. 출력 / 관리
- [ ] **결과 다운로드**(.txt / .md) 정상
- [ ] **③ 처리 기록** 탭에서 과거 결과 재다운로드
- [ ] **② 엔진 · API 키** 탭에서 사용량(토큰)·Google AI Studio 링크 표시 확인
- [ ] **앞 3쪽 미리보기** → **전체 처리** 흐름

### E. 안정성
- [ ] 대용량/다페이지 PDF에서 진행률·예상시간 표시
- [ ] 처리 중단/재실행 시 정상 동작
- [ ] 실행 → 종료 → 재실행 반복 시 포트 충돌 없는지
