# Intent: 2×2 매트릭스 그림 표 인식 개선 (로컬 OCR)

## 1. 배경 및 문제
- 현재 문제: `01_입력` 기준 원본 `역량강화/스캔서적/2x2Matrix_알렉스로위.pdf` 를 처리한 결과 `02_결과/20261021_032448_2x2Matrix_알렉스로위.md`(461쪽, 표 약 75개)에서 2×2 매트릭스 그림이 아래처럼 불완전하게 복원된다. 2026-10-19 스캔표 복원(`docs/intents/2026-10-19-스캔표_마크다운복원.md`)은 **격자선 표**(사내 보고서) 기준이었고, 이 책의 표는 **칸 바깥에 축 이름이 있는 4분면 도식**이라 맞지 않는다.

  | 증상 | 결과 파일 예시(줄) |
  |---|---|
  | 축 이름이 표 밖 본문으로 흩어짐 | 1474 `적정 가치 선 낮다 높다 품질`, 1482 `낮다 높다 원가절감`, 245 `아니오` |
  | 세로로 쓴 축 글자가 잡음으로 읽힘 | 492 `R영올`, 1825 `눈올 뭐마래프`, 1592 `…이키터원지제프` |
  | 그림 제목이 본문 문단 중간에 붙음 | 238 `…두려움, 욕심 그림0.1 이익 계획 매트릭스`, 1592 `…기존 시 그림5.9제품-시장 딜레마…` |
  | 2×2인데 행이 쪼개지거나 빈 행이 생김 | 486–491 그림1.5(5행+빈 행), 1818–1823 그림6.4(5행), 3488–3491 빈 행 |
  | 칸 글자 오인식 | 2941 `경명사`, 2984 `계를`, 2877 `화장`(확장으로 **추정**), 1449 `Southem` |

- 영향받는 업무/사용자: 경영서 스캔본을 텍스트로 받아 읽거나 위키·책 스킬(`book-pipeline`)에 넣는 사용자. 지금은 어느 칸이 어느 축의 어느 쪽인지 원본 PDF를 다시 열어야 안다.

## 2. 목표
- 달성하려는 결과: 2×2 매트릭스를 **축 이름을 머리행·머리열에 둔 Markdown 표**로 출력한다. 이 책은 시험 표본이고 개선은 엔진 일반(로컬 경로)에 적용한다.

  ```
  그림5.4 FTXS의 고객가치 분석 매트릭스

  | 가격 \ 품질 | 낮다 | 높다 |
  | --- | --- | --- |
  | 높다 | 시장 점유율 하락영역 경쟁자2 | 경쟁자1 |
  | 낮다 | FTXS 시장점유율 상승영역 |  |
  ```
  (모양 예시 — 실제 축·칸 값은 원본 확인 후 정답표에 기록)

- 성공 기준(대표 10장, 로컬 엔진만):
  1. **축 이름**: 10장 중 축이 있는 그림의 가로·세로 축 이름과 양 끝 값(낮다/높다 등)이 머리행·머리열에 들어간다 — 정답 대비 일치 **8장 이상**
  2. **격자 모양**: 2×2 그림은 내용 2행 × 2열(+머리행·머리열)로 나온다. 빈 행·쪼개진 행 0건(10장 기준)
  3. **잡음 제거**: 10장 주변에 세로 축 글자 잡음 줄(`R영올` 유형) 0건 — 회전 판독 성공 시 축 이름으로, 실패 시 삭제
  4. **그림 제목 분리**: 10장 모두 `그림N.N 제목` 이 본문 문단에서 떨어져 표 바로 위 독립 줄
  5. **칸 글자**: 10장 4분면 칸 글자 정답 대비 일치율이 지금보다 오르고 **90% 이상**
  6. **회귀 없음**: `python -m pytest engine/tests` 전부 통과(SI운영방안 등 기존 정답 표 테스트 포함) + 본문 글자 수가 표 영역 밖에서 줄지 않음(누락 0)

## 3. 범위
### 포함
- 2×2(및 2×N) 매트릭스 그림 인식: 4분면 칸 + 칸 밖 축 이름·양 끝 값을 묶어 한 표로
- 세로 축 글자 영역을 90° 돌려 RapidOCR 로 다시 읽기, 실패하면 잡음으로 삭제
- 한 칸 안 여러 줄을 한 칸으로 합치기(행 쪼개짐·빈 행 정정)
- 그림 제목(`그림N.N …`) 을 본문에서 떼어 표 바로 위 줄로
- 칸 글자 오인식 교정 — 기존 로컬 교정 사전·규칙(`dicts/`·`engine/user_typos.tsv` 계열)을 칸 글자에도 적용
- `.txt`·`.md` 동일 적용

### 제외
- Vision LLM(Gemini·Claude·Ollama) — **로컬(RapidOCR·OpenCV)만** (사용자 결정 2026-10-21, 일괄 로컬 원칙과 일치)
- 화살표·곡선·점 그림(산점도형 지도의 점 위치) 표현
- 3×3 이상 복잡 도식의 완전 복원(현 수준 유지, 악화만 막음)
- 이미 만든 다른 책 결과의 재처리(필요 시 별도)

## 5. 제약 조건
- 로컬만, API 요금 0
- 기존 격자선 표(SI운영방안) 결과가 나빠지면 안 됨
- 원본 PDF 수정 금지(읽기 전용)
- 본문 무손실 — 표로 옮긴 글자 외에 본문 글자가 사라지면 불합격

## 6. 주요 프로세스
1. 쪽 렌더 → 표/매트릭스 영역 감지(4분면 격자 + 주변 축 글자 영역까지 넓힘)
2. 가로 축 글자(아래·위)·세로 축 글자(왼쪽, 90° 회전 판독) 읽기
3. 4분면 칸 글자 읽기 → 칸 안 여러 줄 합치기 → 로컬 교정
4. 머리행(가로축)·머리열(세로축) 붙여 Markdown 표 생성, 그림 제목을 표 위 줄로
5. 본문에서 표·축·제목으로 옮긴 글자 제거(중복 방지)

## 7. 예외 및 리스크
| 상황 | 처리 방향 |
|---|---|
| 축이 없는 2×2(칸만 있음) | 머리행·머리열 없이 지금처럼 2×2만 |
| 회전 판독 결과가 의미 없는 글자 | 삭제(잡음 처리), 검수기록에 개수 보고 |
| 축 글자가 본문 글자와 붙어 있음 | 표 영역 경계 밖이면 본문으로 남김 — 누락보다 중복을 택함 |
| 산점도형 지도(그림5.5 처럼 칸에 회사명 점) | 칸 소속만 표로, 점 위치 표현은 제외 |
| 일반 격자 표를 매트릭스로 오판 | 기존 표 테스트로 차단 |
