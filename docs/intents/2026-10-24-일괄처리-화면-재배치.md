# Intent: ② 일괄 처리 화면 재배치 — 좌→우 흐름 · 대기열 조작

## 1. 배경 및 문제
- 현재 문제:
  - ② 탭이 위→아래 한 줄로 5블록(방식 → 입력 폴더 → 대기열 → 결과 파일 다시 교정 → 의심 목록). 파일이 많으면 입력 목록이 끝없이 길어지고(`.batch-list` 높이 제한 없음, `ocr_gradio.py:151`) 실행 버튼이 목록 **아래**에 있어 한참 내려가야 누를 수 있다.
  - 대기열은 읽기 전용 표(`batch_runner.status_html`)라 개별 취소·순서 변경이 안 된다. 할 수 있는 건 「대기열 중단(전체)」「끝난 항목 지우기」뿐.
  - 교정 블록 순서가 업무 흐름과 반대 — 의심 목록에서 오타를 등록한 뒤 다시 교정해야 반영되는데, 화면은 다시 교정이 먼저 나온다.
- 영향받는 업무/사용자: 스캔 책을 여러 권 한꺼번에 처리하는 사용자(PM). 처리 → 의심 단어 등록 → 결과 다시 교정 흐름 전체.

## 2. 목표
- 달성하려는 결과: ① 처리하기 탭처럼 **왼쪽→오른쪽으로 흐르고 페이지 세로 스크롤 없이** 고르고 실행하고 조정한다.
- 성공 기준:
  1. ② 탭 안 하위 탭 [처리]·[교정] 각각이 1920×1080 브라우저에서 페이지 세로 스크롤 없이 한 화면에 들어온다(긴 목록은 목록 상자 안에서만 스크롤).
  2. 입력 파일 100개 이상이어도 실행 버튼이 목록 위(또는 옆)에 있어 스크롤 없이 누를 수 있다.
  3. 대기열에서 여러 항목을 골라 취소 · 맨 앞으로 · 한 칸 위/아래 · 다시 시도가 된다. 바뀐 순서대로 다음 파일이 시작된다.
  4. [교정] 하위 탭은 왼쪽 의심 목록 → 오른쪽 결과 파일 다시 교정 순이다.
  5. 기존 테스트(`python -m pytest engine/tests`) 통과 + 대기열 조작 함수 테스트 추가.

## 3. 범위
### 포함
- ② 탭을 하위 탭 2개로 분리
  - **[처리]** 왼쪽: 처리 방식(정제·부속물·저장 형식) + 입력 폴더 + 파일 목록 / 오른쪽: 대기열 + 조작
  - **[교정]** 왼쪽: 의심 목록(넓게) / 오른쪽: 결과 파일 다시 교정
- 입력 파일 목록
  - 목록 상자 높이 고정 + 내부 스크롤, 실행 버튼을 목록 위로
  - 이름 검색칸, 상태 필터(전체 / 미처리 / 완료), 선택 해제 버튼
  - 선택 개수·쪽수 합계 표시(예: "5개 · 1,240쪽 선택")
- 대기열 (체크박스로 고르고 공통 버튼으로 실행)
  - 선택 항목 취소(대기 → 취소, 처리 중 → 그 파일만 중단)
  - 맨 앞으로(우선 처리)
  - 위·아래 한 칸 이동
  - 실패·취소 다시 시도(같은 설정으로 대기열 뒤에 다시 넣음)
  - 기존 「대기열 중단(전체)」「끝난 항목 지우기」 유지
- 다시 교정 목록도 같은 높이 고정·내부 스크롤 적용

### 제외
- ① 처리하기 · ③ 엔진 · ④ 처리 기록 탭 변경
- 일괄 처리 방식 자체(로컬 전용·비용 우선 고정, 동시 처리 수) 변경
- 줄마다 개별 버튼(3초 갱신 표라 누르는 순간 줄이 바뀔 위험 → 체크박스+공통 버튼 방식 채택)
- 끌어다 놓기(드래그)로 순서 바꾸기

## 4. 관련 시스템·데이터
| 구분 | 내용 |
|---|---|
| 대상 시스템 | `engine/ocr_gradio.py` ② 탭 화면(2017~2085행)·이벤트(2302~2388행)·CSS(151행), `engine/batch_runner.py` 대기열(`_jobs`, `submit`·`stop`·`status_html`) |
| 입력 데이터 | 입력 폴더 파일 목록(`batch_runner.list_inputs`), 대기열 작업(`Job`) |
| 출력/결과 | 화면만 변경. 결과 파일·처리 기록·의심 목록 저장 방식은 그대로 |
| 연계 시스템 | ① 탭 「전체 처리」가 대기열 끝에 넣는 경로(`process_full_or_queue`) — 같은 대기열을 쓰므로 조작 대상에 포함 |

## 5. 제약 조건
- 화면 도구 Gradio 그대로(새 패키지 추가 없음).
- 대기열은 작업 스레드가 동시에 읽으므로 순서·상태 변경은 모두 `_lock` 안에서.
- 대기열 화면은 3초마다 갱신 — 갱신돼도 사용자가 체크한 항목이 풀리지 않아야 한다.
- 브라우저를 닫아도 처리가 계속되는 기존 동작 유지.

## 6. 주요 프로세스
1. [처리] 왼쪽: 처리 방식 확인 → 검색·필터로 목록 좁히기 → 체크(선택 개수·쪽수 확인) → 「선택 파일 일괄 처리 ▶」
2. [처리] 오른쪽: 대기열에서 급한 책을 체크 → 「맨 앞으로」, 잘못 넣은 책은 「취소」, 실패한 책은 「다시 시도」
3. [교정] 왼쪽: 책 고르기 → 의심 단어 확인·「고칠 말」 수정 → 「선택 항목 사전 등록」
4. [교정] 오른쪽: 결과 파일 고르기 → 「선택 파일 다시 교정 ▶」 → 의심 목록 갱신

## 7. 예외 및 리스크
| 상황 | 처리 방향 |
|---|---|
| 체크한 대기 항목이 그사이 처리 시작됨 | 「맨 앞으로」·이동은 대기 항목에만 적용, 결과 문구로 "처리 중이라 건너뜀" 안내 |
| 처리 중 항목 취소 | 기존 `cancel` 표시로 그 파일만 중단(정제된 구간은 `*_정제중` 에 남음 — 기존과 동일) |
| 이미 대기·처리 중인 파일을 다시 시도 | 기존 `submit` 규칙대로 중복 넣지 않음 |
| 화면이 작은 노트북(1366×768) | 세로 스크롤이 생길 수 있음 — 목록 상자 높이를 화면 높이 비율(vh)로 잡아 최소화 |
| 검색·필터로 숨겨진 파일이 이미 체크돼 있음 | 숨겨도 선택은 유지하고, 선택 개수 표시에 숨은 것도 포함 |
