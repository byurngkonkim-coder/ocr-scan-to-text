# Intent: 한자 인식 (로컬 OCR 에 한자 판독 추가)

> 기본 증거등급: E2(파일·모델을 직접 열어 센 결과). 재현 명령은 부록.

## 1. 배경 및 문제
- 현재 문제: 로컬 OCR 엔진(RapidOCR 한글 v5)의 글자 사전에 한자가 없어 한자를 아예 못 읽는다.
  - 한글 v5 인식 모델 글자 사전 11,945자 중 한자 0자, 한글 11,172자 ⟦E2✓ 2026-10-18⟧
  - 그 결과 한자 자리가 비거나 엉뚱한 글자가 된다: `출사표()`, `삼고초려()`, `심서(L)`, `신인(시)`
  - 빈 괄호 `()` 수(02_결과): 장원_제갈량 683 · MC_손자병법 166 · 리더의36계 52 · 노자경영 44 · 한비자 8 · 2천년의강의 6 ⟦E2✓⟧
  - 결과에 한자가 일부 있는 책(리더의공자지혜 164자 등)은 Vision 폴백 쪽으로 추정된다 ⟦E3: 추정⟧
- 영향받는 업무/사용자: 손자병법·사기·노자·공자·맹자·한비자 등 고전·경영 고전 책을 텍스트로 만드는 사용자. 한자 병기와 한문 원문이 빠져 문맥이 끊긴다.

## 2. 목표
- 달성하려는 결과: 로컬 엔진만으로 한글 옆 괄호 한자와 한문 원문 문장을 읽어 텍스트에 넣는다. 확실하지 않은 한자는 넣지 않고 비워 둔다.
- 성공 기준 (표본 쪽을 사람이 원본과 대조해 판정):
  1. 넣은 한자 중 틀린 글자 **0건** (표본 3권 × 10쪽 이상)
  2. 표본 책의 빈 괄호 `()` 수가 재처리 전보다 줄어든다 — 감소율을 측정해 보고(목표치는 시험 측정 후 합의, 8번)
  3. 한자가 없는 쪽의 한글 결과는 바뀌지 않는다(한자 없는 책 1권 전체 비교, 바뀐 글자 0)
  4. 한자가 없는 책의 처리 시간 증가 10% 이하
  5. 기존 테스트(`python -m pytest engine/tests`) 실패 0건

## 3. 범위
### 포함
- 로컬 OCR 판독 단계에 한자 판독 추가 — 이미 설치된 중국어 PP-OCRv6 인식 모델(한자 15,565자) 사용 ⟦E2✓⟧
- 대상: 괄호 속 한자 병기(`출사표(出師表)`), 한자 섞인 단어(`형形`), 한문만 있는 줄(`君子周而不比`)
- 한자 흔적이 있는 줄(빈 괄호·이상 글자·저신뢰)만 추가 판독 — 모든 줄 두 번 읽지 않음
- 새로 처리하는 책에 기본으로 켜 둠(①·④ 탭)
- 기존 고전 결과 재처리: 원본 `F:\00스캔서적(인문,철학,종교,고전)\04_경영_전략\` 의 책 중 02_결과에 결과가 있는 고전 책
- 정제 단계(빈 괄호 제거·맞춤법 교정 등)가 넣은 한자를 지우거나 바꾸지 않도록 확인

### 제외
- Vision API(Gemini 등) 사용 — 로컬만
- 추정 한자 넣기·한자 사전으로 한글→한자 자동 변환(원본에 없는 내용을 지어낼 위험)
- 세로쓰기 한문, 손글씨
- `05_인문_고전` 폴더 책은 아직 결과가 없으므로 재처리 대상이 아니라 「새 책」으로 처리

## 5. 제약 조건
- 로컬·무료만. 새 패키지 설치 없음(모델은 이미 `rapidocr/models` 에 있음)
- 이동식(USB) 배포본 `engine/python` 에서도 동작
- 오인식 0건 원칙 — 확실하지 않으면 비워 둔다
- 기존 결과를 덮어쓸 때는 `_백업/` 에 먼저 보관

## 6. 주요 프로세스
1. 한 쪽을 지금처럼 한글 모델로 읽는다.
2. 한자 흔적이 있는 줄을 고른다(빈 괄호, 한글 모델 저신뢰 글자 구간, 한문으로 보이는 줄).
3. 그 줄만 한자 모델로 다시 읽고, 한자 모델이 확신하는 한자만 같은 위치에 끼워 넣는다. 한글은 한글 모델 결과를 유지한다.
4. 정제·교정을 거쳐 결과 파일로 저장한다.
5. 재처리: 대상 고전 책을 원본 PDF로 다시 OCR → 기존 결과 백업 후 교체.

## 7. 예외 및 리스크
| 상황 | 처리 방향 |
|---|---|
| 한자 모델이 한글을 비슷한 한자로 잘못 읽음(예: `工`↔`ㅗ`) | 한글 모델이 확신하는 구간은 바꾸지 않음. 표본 대조로 0건 확인 |
| 두 모델의 글자 위치가 어긋나 엉뚱한 자리에 끼움 | 글자 위치(좌표) 정렬 실패 시 넣지 않고 비워 둠 |
| 처리 시간 급증 | 흔적 있는 줄만 추가 판독. 시간 측정 보고 |
| 재처리 중 기존 결과 손실 | 백업 후 교체, 새 결과 분량이 크게 줄면 교체하지 않음 |
| 시험 결과 정확도가 기준 미달 | 구현 전 시험 측정(8번)에서 판정 — 미달이면 방향을 다시 상의 |
