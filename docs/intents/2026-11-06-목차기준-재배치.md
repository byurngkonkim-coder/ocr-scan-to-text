# Intent: 결과 파일 목차 추출 · 목차 기준 재배치(후처리)

<!-- 기본 증거등급 E2(이 세션에서 02_결과 64개를 스크립트로 측정). 예외는 인라인 표기 -->

## 1. 배경 및 문제
- 목적: 스캔 책(이미지 OCR·텍스트 레이어 PDF 양쪽) 추출 결과를 **장별 요약·활용**할 수 있게, 목차 기준으로 장·절 경계가 분명한 결과를 만든다.
- 지금 있는 것: `toc_headings`(차례 쪽 읽기 → 본문 같은 줄을 `#` 제목으로), `text_cleaner.infer_chapters`(차례 없을 때 '제N장·CHAPTER N' 줄로 추정), `remake_md`(02_결과 MD 에 장·절 제목 재적용, OCR·API 0회), `notebooklm.split_parts`(큰 책만 장 경계 분할).
- 현재 문제(02_결과 MD 64개 측정, 2026-11-06):
  - **16개가 "차례를 찾지 못해 장·절 정비 없이 정제"** — 장 제목 0개(1권은 1개).
  - 그중 3권(MaximumAchievement·TurboStrategy·경영바이블)은 결과 안에 차례가 **있는데** 인식 실패 — 한 줄에 여러 항목이 `I` 로 이어지거나, 영문 점선(`Preface......ix`)·`Chapter` 다음 줄 번호 꼴.
  - 나머지 13권은 결과 텍스트에 '차례·목차·Contents' 줄 자체가 없음 — 정제 때 빠졌거나 OCR 이 못 읽은 것으로 ⟦E3: 추정, 원문 사본 미확인⟧.
  - 차례를 찾은 48권도 본문 순서가 차례 순서와 어긋나는 경우(쪽 순서 오류 등)를 바로잡는 기능은 없음.
- 영향받는 사용자: 스캔 경영서를 OCR → 장별 요약·NotebookLM 질의에 쓰는 사용자 본인.

## 2. 목표
- 달성하려는 결과: **기존 추출 과정은 그대로 두고**, 결과 파일(md·txt)을 입력으로 받는 후처리 단계에서
  1. 목차를 확보하고(결과·원문 사본 → 알라딘 목차 순),
  2. 본문을 목차 기준 장·절로 경계 짓고(한 파일 안 `#`·`##` 제목),
  3. 목차 순서와 어긋난 장·절 덩어리는 목차 순서로 옮긴다.
- 성공 기준(확인 가능한 형태):
  - 차례 없음 16권 → 장 제목이 1개 이상 붙은 책 수 측정(목표치는 §8-4에서 확정).
  - 차례 있는 책의 차례 항목 대 본문 제목 연결률 — 재배치 전후 비교, 떨어진 책 0권.
  - **글자 무손실**: 재배치 전후 본문 글자(공백·제목 표시 제외) 다중집합이 같다 — 책마다 자동 검사.
  - 장 경계로 잘라 낸 장별 덩어리가 목차 항목과 1:1 대응(대응 못 한 항목은 보고서에 이름으로 나열).
  - 덩어리 이동이 있었던 책은 이동 목록(어느 장을 어디서 어디로)이 보고된다.

## 3. 범위
### 포함
- 입력: 02_결과의 `.md`·`.txt`(정제 결과). 원문 사본(정제 전)은 차례 찾기·쪽 대조에만 읽는다.
- 목차 확보 순서: ① 결과 앞부분 차례 ② 원문 사본 앞부분 차례 ③ 알라딘 Open API 도서 목차 ④ 본문 장 번호 추정(현행 `infer_chapters`).
- 차례 인식 보강: `I`·`|` 구분 한 줄 다항목, 영문 점선 꼴, `Chapter` 와 번호가 줄로 갈린 꼴.
- 결과 형태: **한 파일** — 장·절 제목(`#`·`##`)으로 경계가 분명해 장 단위로 잘라 요약할 수 있는 MD. 맨 앞 차례 목록에 목차 출처(결과/원문 사본/알라딘/추정) 표기.
- 순서 이동: **장·절 덩어리 단위만**(제목~다음 제목). 단락 내부·단락 단위 이동은 하지 않는다.
- 원본 처리: `_백업/` 에 보관 후 원본 자리에 교체(`remake_md`·`reclean` 방식).
- 실행: 02_결과 일괄 + 파일 하나 지정.
### 제외
- 기존 추출 과정(OCR·텍스트 레이어 추출·정제) 변경, 원본 PDF 재OCR.
- LLM 으로 장 경계·제목 생성, 장별 요약 생성(원문 근거만 — 2026-10-24 결정 유지).
- 단락 단위 재배치.
- 장별 별도 파일 출력(필요하면 기존 `notebooklm.split_parts` 처럼 후속 과제).

## 4. 관련 시스템·데이터
| 구분 | 내용 |
|---|---|
| 대상 시스템 | `engine/core/toc_headings.py`(MyOCR 와 바이트 동일 공유), `text_cleaner.rematch_headings·infer_chapters`, `remake_md.py` |
| 입력 데이터 | `02_결과/*.md·*.txt`, 저장된 원문 사본(`remake_md._raw_copy`), 파일명의 책 제목·저자 |
| 출력/결과 | 같은 자리의 MD/TXT(장·절 제목·차례 목록·목차 출처), `_백업/재배치_{시각}/` 원본, 처리 보고(연결률·이동 목록·미대응 항목) |
| 연계 시스템 | 알라딘 Open API(TTB 키) — 도서 검색 → 상품 조회 목차 |

## 5. 제약 조건
- 원문 글자 무손실 — 덩어리 이동만, 글자 추가는 제목 표시·차례 목록·출처 줄뿐.
- 알라딘 목차는 **본문에 같은 제목 줄이 있을 때만** 장 경계로 쓴다(외부 목차가 본문을 지어내지 않게). 판본 차이로 어긋날 수 있다.
- `toc_headings.py` 수정 시 MyOCR 사본도 함께(`test_toc_headings.py` 바이트 동일 검사).
- 새 외부 패키지 없음 목표(HTTP 는 표준 라이브러리 `urllib`) — 계획 단계에서 확인.
- API 키는 `.env`/설정 파일(보호 경로)로, 코드에 넣지 않는다.

## 6. 주요 프로세스
1. 대상 결과 파일 선택(일괄/단건) → `_백업/재배치_{시각}/` 에 보관.
2. 목차 확보: 결과 앞부분 → 원문 사본 앞부분 → 알라딘(제목·저자 검색, 후보 1건으로 좁혀질 때만) → 본문 장 번호 추정.
3. 목차 항목을 본문 줄과 맞춰 장·절 제목 표시(현행 `rematch_headings` 재사용).
4. 본문에서 찾은 제목 순서가 목차 순서와 다르면, 해당 장·절 덩어리를 목차 순서로 옮김.
5. 무손실 검사 → 통과하면 교체, 실패하면 원본 유지 + 보고.
6. 보고: 책별 목차 출처·연결률·미대응 항목·이동 목록.

## 7. 예외 및 리스크
| 상황 | 처리 방향 |
|---|---|
| 알라딘 검색 결과 여러 권·판본 다름 | 자동 적용 안 함, 후보를 보고서에 남김 |
| 알라딘 목차 없음/키 없음/네트워크 실패 | 다음 단계(본문 추정)로, 실패 사유 보고 |
| 목차 제목이 본문에 일부만 있음 | 찾은 항목만 표시, 미대응 항목 나열 |
| 순서 어긋남이 OCR 제목 오인식 때문(진짜 이동 아님) | 이동 조건을 보수적으로(§8-3), 이동 목록 보고로 사람 확인 |
| 장 앞 머리말·서문(목차 밖 글) | 첫 장 앞 덩어리로 두고 이동하지 않음 |
| 무손실 검사 실패 | 교체하지 않음 |

## 8. 미해결 질문
1. 알라딘 TTB 키 보유 여부 · 상품 조회 API 가 목차를 주는지(`OptResult=Toc` 등) ⟦E0: 미확인, search-first 단계에서 공식 문서로 확인⟧
2. 원문 사본이 13권 각각에 있는지, 사본 앞부분에 차례가 남아 있는지 ⟦미측정⟧
3. 덩어리 이동 조건 — 예: 목차 순서와 다른 제목이 2개 이상 연속, 쪽 표지 `[p.N]` 순서도 같은 방향으로 어긋날 때만 이동 등
4. 성공 기준 목표치 — 차례 없음 16권 중 몇 권 이상을 장 경계 확보로 볼지
5. 대시보드 버튼으로 둘지(기존 재변환 화면에 추가) / 명령줄만으로 둘지
6. `.txt` 결과(현재 02_결과는 MD 64개뿐)에 같은 처리를 하되 제목 표시 꼴을 MD 와 같게 할지
