# Intent: 결과를 .txt 와 .md 로 함께 저장

## 1. 배경 및 문제
- 현재 문제: 대시보드 「저장 형식」 라디오에서 `txt`·`md` 중 **하나만** 고를 수 있다(`ocr_gradio.py` 1665행, 기본값 `config.default_format`). 둘 다 필요하면 같은 파일을 두 번 처리해야 한다.
- 2026-10-19 표 복원(`docs/intents/2026-10-19-스캔표_마크다운복원.md`) 이후 결과 본문에 Markdown 표가 들어가므로, `.md` 로 열면 표로 보이고 OKF 지식위키에 넣어도 표가 유지된다.
- 영향받는 업무/사용자: OCR 결과를 메모장(.txt)으로 읽고, 같은 결과를 OKF 지식위키 등록·MD 뷰어(Obsidian·VS Code) 열람에도 쓰는 사용자.

## 2. 목표
- 달성하려는 결과: 한 번 처리로 `02_결과/` 에 같은 본문의 `.txt` 와 `.md` 가 짝으로 생긴다.
- 성공 기준:
  1. 「저장 형식」에 `txt+md` 선택지가 생기고, 고르면 `02_결과/<시각>_<원본명>.txt` 와 같은 이름의 `.md` 가 함께 생긴다
  2. 두 파일의 본문이 바이트 단위로 같다(정제 켠 경로 기준)
  3. `txt`·`md` 단독 선택은 지금과 결과가 같다(회귀 없음)
  4. 대시보드 전 경로에서 동작: 스캔 OCR · 디지털 PDF · txt 정제 · 검토 쪽 다시 읽기 · ④ 일괄 처리
  5. `python -m pytest engine/tests` 전부 통과 + 새 동작 테스트 추가

## 3. 범위
### 포함
- 「저장 형식」 라디오에 `txt+md` 추가, `config.json` 기본값으로도 고를 수 있게
- 결과 확정 지점(`_finalize_results`·`_publish_to_results`, `ocr_gradio.py` 824·1445·1566행)에서 짝 파일 생성
- 정제 중 임시 파일(`_정제중`)·정제 전 원문 사본(raw) 처리 규칙을 짝 저장과 어긋나지 않게
### 제외
- CLI `ocr_tool.py --format`(사용자 선택: 대시보드만)
- MD 머리말(제목·문서 정보) 추가 — 본문은 TXT 와 같게
- OKF 지식위키 자동 등록(사용자가 MD 를 옮겨 넣는 흐름은 그대로)

## 4. 관련 시스템·데이터
| 구분 | 내용 |
|---|---|
| 대상 시스템 | `engine/ocr_gradio.py`(형식 선택·결과 확정), `engine/core/writer.py`, `engine/core/types.py`(`OutputFormat`), `engine/core/storage_manager.py`(처리 기록), `engine/batch_runner.py`(④ 일괄 처리) |
| 입력 데이터 | `01_입력/` 의 PDF·이미지·txt |
| 출력/결과 | `02_결과/<시각>_<원본명>.txt` + `.md` |
| 연계 시스템 | OKF 지식위키(`.md` 를 sources 에 넣어 색인), MD 뷰어 |

## 5. 제약 조건
- 새 외부 패키지 없음
- 기존 `txt`·`md` 단독 저장 동작·파일명 규칙 유지
- 처리 기록(`engine/storage/history.json`)은 지금 실행당 결과 경로 1개(`result_path`)만 저장 — 구조를 바꾸면 이전 기록 읽기와 호환 유지

## 6. 주요 프로세스
1. 사용자가 「저장 형식」에서 `txt+md` 를 고르고 처리 실행
2. 처리·정제는 지금과 같이 한 번만 수행
3. 결과 확정 시 같은 본문을 `.txt` 와 `.md` 로 각각 저장
4. 화면 「저장 위치」·처리 기록에 두 파일이 보인다

## 7. 예외 및 리스크
| 상황 | 처리 방향 |
|---|---|
| 정제를 끈 경로 — TXT 는 `[페이지 N]`, MD 는 `## 페이지 N`·문서 정보 머리말로 서식이 다름(`writer._build_txt`/`_build_md`) | §8 질문 1 |
| 짝 중 하나 저장 실패 | 성공한 파일은 남기고 실패를 화면 로그에 표면화(지금 `_finalize_results` 의 경고 방식) |
| 같은 시각 이름 충돌 | 두 파일이 같은 시각 접두를 쓰게 한 번만 시각을 구한다 |

## 8. 미해결 질문 → 결정 (2026-10-19, 사용자)
1. 정제를 끈 경로: `.md` 는 **기존 MD 서식 유지**(`writer._build_md` — `## 페이지 N`·문서 정보 머리말). 이 경로에서는 성공 기준 2(본문 동일)를 적용하지 않는다
2. 처리 기록은 **`.txt` 가 주 결과**(`result_path`), `.md` 는 같은 이름 짝으로 둔다. 화면 결과 받기는 **두 파일 모두** 내려받게 한다
3. `config.json` 기본 형식은 **그대로**(`txt`) — 손대지 않는다

## 10. 구현 결과 (2026-10-19)

| 4. 대시보드 전 경로 | 코드 반영, 실물은 스캔 OCR 만 확인 | 디지털 PDF·txt(`_run_digital_pdf`)·검토 쪽 다시 읽기(`reread_review_pages`)·④ 일괄 처리(`_run_ocr` 공용)에 같은 헬퍼 적용. 이 셋은 실물로 돌려 보지 않았다 |

구현: `_parse_fmt`(형식 해석) · `_md_pair_source`(정제·txt 원문은 같은 글자, 정제 끈 쪽 단위 출력은 기존 MD 서식) · `_place_md_pair`(실패 시 로그로 표면화) · `_result_files`(결과 칸·기록 다운로드에 두 파일). 「저장 형식」·「기본 저장 형식」 라디오에 `txt+md` 추가, `config.json` 기본값은 그대로.

**알려진 한계**: 처리 기록 삭제(파일 함께 지우기)는 `.txt` 만 지우고 `.md` 짝은 남는다 · CLI `ocr_tool.py` 는 범위 밖.
