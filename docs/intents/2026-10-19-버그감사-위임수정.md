# Intent: 버그 감사 30건 위임 수정

## 1. 배경 및 문제
- 현재 문제: 2026-10-18 코드 감사(에이전트 6개 + 직접 재현)에서 실제 서비스 장애·데이터 손실로 이어질 수 있는 버그 30건(치명 2·높음 13·중간 15)과 잠복 1건이 나왔다. 대표 사례: 정제 단계가 한문 줄·한자를 지움(손자병법 40–47쪽 한자 184→74자), 일괄 처리 중 Kiwi 충돌로 서버 프로세스 종료, 쪽 그리기 실패 시 부분 결과를 「완료」로 확정.
- 영향받는 업무/사용자: OCR 도구 사용자(비개발자)의 ① 단건·④ 일괄 처리 전 과정. 특히 14권 재OCR 착수 전에 고쳐야 결과를 믿을 수 있다.

## 2. 목표
- 달성하려는 결과: 감사 목록 30건(+잠복 1건)을 사용자 확인 없이 끝까지 처리한다(권한 위임). 버그마다 재현 → 추천안 수정 → 회귀 테스트 → 전체 테스트 통과 → 커밋.
- 성공 기준:
  - 각 버그가 「수정(커밋 해시)」 또는 「보류(재현 안 됨, 근거)」 중 하나로 판정된 결과표가 있다.
  - 수정한 버그마다 회귀 테스트가 1개 이상 있고, 수정 전 실패·수정 후 통과를 확인했다.
  - `python -m pytest engine/tests` 전체 통과(커밋마다).
  - 1번(한자 삭제)은 손자병법 40–47쪽 정제 후 한자 수가 OCR 단계 수(184)에 근접하고 「未戰而廟算」「新井白石」「般若心經」이 남는다.

## 3. 범위
### 포함
- 감사 목록 1~30번 + 잠복 1건(hanspell 띄어쓰기 손실), 치명 → 높음 → 중간 순.
- 버그마다 감사 보고서의 추천안 적용. 추천안이 재현 결과와 맞지 않으면 다른 안을 골라 진행하고 결과표에 사유를 적는다.
- 버그 수정에 필요한 최소한의 기존 테스트 기대값 조정(사유를 커밋 메시지에 기록).
- 매뉴얼 문구가 버그의 일부인 경우(17번 「탭 닫아도 된다」 안내)의 문서 수정.
### 제외
- main 병합·GitHub 푸시(끝난 뒤 사용자에게 묻는다).
- 14권 재OCR, 사용자의 중단된 책 2권(`Delete_전병국`, `DrivingSalesmanPowerSkill`) 처리.
- 코드 스타일·리팩터링·새 기능.
- 실제 유료 API 호출(키 읽기·출력 포함). 유료 경로는 가짜 응답으로만 검증.

## 5. 제약 조건
- 시작 전 복구 지점: 태그 `bugfix-start-20261018`(f02d302), config.json 백업 완료.
- 버그 하나씩 수정·커밋(`fix:` 태그, Co-Authored-By 줄).
- 재현되지 않으면 수정하지 않고 보류.
- 일괄 처리는 로컬 전용·API 요금 최소화 원칙 유지.
- 실행 중 서버는 사용자 확인 없이 끄거나 재시작하지 않는다.
- 원본 입력(F:, `01_입력/`)은 읽기만 한다.
- 위임 범위: 중간에 멈추지 않고 끝까지 진행, 마지막에 한 번 보고(사용자 결정 2026-10-19).

## 6. 주요 프로세스
1. 버그 n번 재현 스크립트 실행 → 재현 여부 판정(안 되면 보류 기록 후 다음 번호).
2. 회귀 테스트 작성 → 수정 전 실패 확인.
3. 추천안으로 수정 → 회귀 테스트 통과 → 전체 테스트 통과.
4. 커밋 → 결과표 갱신 → 다음 번호.
5. 전부 끝나면 결과표 보고, effort 낮추기 안내, main 병합·푸시 여부 질문.

## 7. 예외 및 리스크
| 상황 | 처리 방향 |
|---|---|
| 재현 안 됨 | 보류, 결과표에 시도한 방법 기록 |
| 추천안이 재현 결과와 안 맞음 | 다른 안으로 진행, 사유 기록(멈추지 않음) |
| 수정이 기존 테스트를 깨뜨림 | 기존 기대값이 버그를 굳힌 것이면 조정·사유 기록, 아니면 수정 방식 변경 |
| 새 외부 패키지가 필요 | 패키지 없이 가능한 안으로 대체. 불가하면 보류 |
| 서버 재시작이 있어야 확인되는 버그(17·25번 등) | 코드·테스트로만 확인, 실서버 확인은 결과표에 「미확인」 |
| 수정 간 충돌(같은 파일 여러 버그) | 번호 순서대로 순차 처리 |
| 세션 컨텍스트·사용 한도 소진 | 결과표를 남기고 다음 세션에서 이어 함 |
