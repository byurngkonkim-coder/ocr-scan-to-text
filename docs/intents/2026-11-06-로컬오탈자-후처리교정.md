# Intent: 로컬 오탈자 후처리 교정 — OCR 혼동 글자 후보 + Kiwi 점수 비교

> 기본 증거등급: E2 (실측 스크립트는 세션 scratchpad, 재현 방법은 부록). 사용자 결정은 E1(2026-11-06 대화).
> 개정: 초안(로컬 LLM exaone3.5 + 출력 검증 필터) → 수정본(Kiwi 점수 비교, 사용자 결정 2026-11-06 "Kiwi 방식으로 고쳐").

## 1. 배경 및 문제
- 현재 문제: 내장 규칙 정제·Kiwi 띄어쓰기(R-17)·오타 사전을 거친 뒤에도 OCR 결과에 **한 글자 오인식**이 남는다(`일휼`·`힘올`·`양형들`·`경쟀이란`·`구메하고`·`한게가`, 『악당의 명언』 실측).
- 목적(사용자 답변): 기존 맞춤법 검사·단락·줄 검사를 거친 뒤 **후처리로 띄어쓰기 교정과 오탈자 교정**. API 키 없이 로컬로.
- 띄어쓰기: 기존 R-17(`core/spacing.py`, Kiwi)이 이미 담당 — 이번 범위에서 새로 만들지 않는다.
- 검토하고 버린 방법(2026-11-06 실측, 『악당의 명언』):
  | 방법 | 결과 | 판정 | EG |
  |---|---|---|---|
  | 로컬 LLM 통째 교정(exaone3.5:7.8b, CPU) | 1,118자에 121초, 뜻 바꿈(`해적왕→도적왕`)·지어냄, 무결성 가드 2회 중 2회 거부 | 버림 — 느리고 내용 보존 안 됨 | E2 |
  | 규칙 뒤 제한 프롬프트(4종만 수정, 재작성·요약·어휘 개선·의미 변경 금지) | 769자에 89~114초, 금지 명시판이 위험 변경 15→26곳으로 오히려 증가 | 버림 — 프롬프트로 못 막음, 책 1권 3시간 이상 | E2 |
  | Kiwi 의심 목록 항목만 LLM 판정 | 책 1권 의심 17개, 약 6분. 고친 11곳 중 맞은 것 2곳(`일음→이름` 등 오답), `일휼`·`힘올`·`양형`은 목록에 안 걸림 | 버림 — 후보를 못 잡고 판정도 틀림 | E2 |
  | **원문 vs 한 글자 바꾼 문장의 Kiwi 점수 비교** | 13쌍 중 13쌍 정답(`일을`·`경쟁`·`제안을`·`하늘`·`적게`, 맞던 `지나버리는`·`궁금한` 유지), 13쌍 0.9초 | **채택** | E3 |
  ⟦E3: 정답 후보를 사람이 넣어 준 시험이라 후보 자동 생성을 붙였을 때의 정확도는 추정이며 미검증⟧
- 영향받는 업무/사용자: 스캔 책을 텍스트로 바꿔 위키·책 스킬 원본으로 쓰는 사용자(PM 본인).

## 2. 목표
- 달성하려는 결과: 결과 txt의 각 한글 어절에 대해
  1. **후보 생성** — OCR이 자주 헷갈리는 자모 짝(혼동표)으로 한 글자씩 바꾼 후보를 만든다(`휼·올→을`, `메→매`, `게→계`, `쟀→쟁` 등).
  2. **점수 비교** — 원문 문장과 후보 문장을 Kiwi로 분석해 점수를 비교하고, 점수 차가 기준 이상인 후보만 남긴다.
  3. **반영** — 1단계(이번 범위): 본문은 바꾸지 않고 기존 의심 목록(`02_결과/_의심목록/{책}.tsv`)에 올린다. 사용자가 확인해 `user_typos`에 등록한 것만 다음부터 고친다(10-17 intent와 같은 흐름). 2단계(측정 후 별도 결정): 오교정률이 확인된 점수 구간만 자동 반영.
- 성공 기준:
  1. **한글 손실 0자** — 1단계는 본문 글자를 바꾸지 않는다(후처리 전후 본문 동일, 재교정 전후 글자 비교로 확인).
  2. 표본 책에서 후보 목록의 **정답률을 측정해 보고**(점수 차 구간별 맞음/틀림 건수) — 2단계 자동 반영 여부를 정하는 근거.
  3. 책 1권(약 7만~10만 자) 처리 시간 수 분 이내 ⟦E3: 0.07초/쌍 실측에서 추정⟧.
  4. `python -m pytest engine/tests` 실패 0건.

## 3. 범위
### 포함
- 혼동표 기반 후보 생성 + Kiwi 점수 비교 모듈.
- 기존 의심 목록에 후보 추가(기존 Kiwi 오타 모드 항목과 함께).
- 실행: 처리 끝난 결과에 따로 실행(사용자 결정) — ② 탭 「기존 결과 재교정」과 같은 경로.
- 표본 책 정답률 측정.
### 제외
- 로컬 LLM(exaone3.5) 사용 — 이번 실측으로 버림. 기존 `local_cleanup_engine: "ollama"` 경로는 손대지 않음.
- 띄어쓰기 새 기능(기존 R-17 유지).
- 본문 자동 반영(2단계는 측정 결과를 보고 별도 결정).
- 외부 API·외부 검사기.

## 5. 제약 조건
- 로컬 전용, 새 외부 패키지 없음(Kiwi는 이미 있음).
- 무손실 최우선(L0 §4) — 1단계는 본문을 바꾸지 않는다.
- 보호 경로(`.env`, `config/**`, `legacy/**`, `_보관/**`)는 건드리지 않는다.

## 6. 주요 프로세스
1. 사용자가 ② 탭에서 결과 txt를 고르고 재교정(또는 후처리) 실행.
2. 한글 어절마다 혼동표로 한 글자 바꾼 후보를 만든다.
3. 원문 문장·후보 문장을 Kiwi로 분석해 점수 차를 계산, 기준 이상만 남긴다.
4. 남은 후보를 의심 목록에 추가(틀린 말·제안·횟수·문맥, 점수 차 표시).
5. 사용자가 목록에서 확인 → `user_typos` 등록 → 다음 처리·재교정부터 자동 교정.

## 7. 예외 및 리스크
| 상황 | 처리 방향 |
|---|---|
| 고유명사·외래어를 흔한 낱말로 바꾸자고 함(`하눈→하늘` 류) | 1단계는 목록만 — 사람이 거름. 정답률 측정에 포함 |
| 혼동표가 넓어 후보가 너무 많음 | 점수 차 기준을 올려 목록 크기 조절, 측정으로 기준 결정 |
| 한 문장에 오타가 여럿 | 한 글자씩 따로 평가(조합 폭발 방지) — 놓치는 경우는 한계로 기록 |
| 잡음 기호가 섞인 깨진 문장 | 점수가 원래 낮아 오판 가능 — 측정에서 확인 |
| Kiwi 미설치 | 기존 의심 목록처럼 건너뜀 |

## 8. 미해결 질문
1. 혼동표 범위 — 실측 사례(`ㅡ↔ㅜ`, `을↔올↔휼`, `ㅐ↔ㅔ`, `ㅖ↔ㅔ`, 받침 차이)로 시작할지, 더 넓힐지.
2. 점수 차 기준값 — 표본 측정 후 정함.
3. 실행 시점 — Kiwi는 빨라서(수 분 이내 추정) OCR 처리 중 자동 실행도 가능하다. 「끝난 결과에 따로 실행」 결정을 유지할지.
4. 표본 책 선정 — 명언집 외 일반 본문 책 포함 여부.

## 10. 구현 결과 (2026-11-06)
- 구현: `engine/core/ocr_typos.py`(혼동표 `TypoTransformer` + 점수 차, 별도 Kiwi 인스턴스), `typo_suspects.find()` 에 합침, 측정 도구 `engine/tools/ocr_typo_eval.py`, 테스트 `engine/tests/test_ocr_typos.py`.
- 표본 측정(『악당의 명언』 371쪽, 후보 115개, 판정은 사람이 문맥을 보고 정한 추정 ⟦E3⟧):
  | 점수 차 | 맞음 | 틀림 | 정답률 | EG |
  |---|---|---|---|---|
  | 8 미만 | 1 | 38 | 3% | E3 |
  | 8~16 | 18 | 25 | 42% | E3 |
  | 16 이상 | 23 | 4 | 85% | E3 |
  → `MARGIN_MIN = 8.0` 유지(8 미만은 버림). 의심 목록에 오르는 74개 중 맞음 41개(모름 4개) — 기존 Kiwi 오타 모드(같은 책 17개)보다 많이 잡는다. 16 이상도 85%라 **자동 반영(2단계)은 아직 안 함**. 틀린 16 이상 4건은 `았→었`·`나버→나비` 꼴.
- 처리 시간: 책 1권 약 2초(후보 생성·점수 비교) ⟦E2⟧.
- 성공 기준: ① 본문 변경 없음 — 테스트로 고정 ② 정답률 보고 — 위 표 ③ 수 분 이내 — 약 2초 ④ 테스트 — 819 passed, 실패 4건은 이번 변경과 무관한 기존 문제(`matrix_p106.png` 등 표본 이미지 미커밋, `toc_headings.py` 가 MyOCR 사본과 다름).
- 알려진 한계: 두 자모가 같이 틀린 오인식(`일휼`, `양형`, `경쟀`)은 못 잡음. 의심 목록 문맥은 그 낱말이 처음 나온 곳이라, 바른 낱말 안에 든 조각(`이디→이더`, 49회)은 등록하면 바른 낱말을 망칠 수 있다 — 횟수가 크면 등록 전 확인.
