# Intent: 정제 순서 재배치 (구조 복원 → 노이즈 → 맞춤법) + 최종 검수 기록

> 기본 증거등급: E2(코드를 직접 읽어 확인). 참고 문서: 사용자 첨부 「권장 정제 순서.md」(2026-10-18).

## 1. 배경 및 문제
- 현재 문제: 노이즈·맞춤법·띄어쓰기 오류, 단락 미구분, 어절 끊김·붙음이 많은 스캔 책에서 **맞춤법·띄어쓰기 교정이 줄 잇기·노이즈 제거·쪽 경계 잇기보다 먼저** 돈다. 끊기거나 잡음이 섞인 문장을 기준으로 교정해 교정 효과가 떨어지고 오교정 위험이 커진다 ⟦E3: 추정 — 실측으로 확인할 항목⟧
- 지금 순서 ⟦E2⟧:
  - 쪽마다(`engine/ocr_gradio.py:610-630`): ① 깨진 글자 정리(`char_normalizer`) → ② 맞춤법·띄어쓰기·어절 교정(`refine_korean_text`) → ③ 사용자 오타 사전 → ④ 맞춤법 검사기(설치 시) → ⑤ 쪽번호·잡음 줄 제거 → 줄 잇기 → 공백 정리(`postprocessor.process_full`, `core/postprocessor.py:87-98`)
  - 책 전체(`core/text_cleaner.py:671-679`): 머리글·부속물·쪽번호 제거(R-01~R-16) → 쪽 경계 문장 잇기 → R-17 띄어쓰기(Kiwi)
- 첨부 문서 권장: 품질 점검 → 레이아웃 → 블록 분리 → 줄·어절 병합 → 노이즈 제거 → 맞춤법·띄어쓰기 → 용어·수치 검증 → 최종 검수(원문↔정제본 비교·수정 기록)
- 영향받는 업무/사용자: 스캔 책을 텍스트로 만드는 사용자(①·④ 탭).

## 2. 목표
- 달성하려는 결과: 맞춤법·띄어쓰기·오타 교정을 **쪽번호·잡음 제거와 줄·쪽 경계 잇기가 끝난 뒤**에 한 번 돌린다. 책마다 OCR 원문↔정제본 비교 요약을 남긴다.
- 노이즈 제거는 줄 잇기보다 **앞**에 둔다(문서 권장 4→5 와 다름). 근거: 쪽번호가 문장 사이에 붙은 실제 사례 `그러 23 니`(정제규칙서 R-16) — 잇기 전에 떼야 한다.
- 성공 기준 (표본 3권 이상, 기존 순서 vs 새 순서 같은 OCR 원문으로 비교):
  1. 글자 손실 없음 — 한글·한자·숫자 글자 수 차이가 띄어쓰기·교정 규칙으로 설명되는 범위 안(설명 안 되는 손실 0건)
  2. 오교정 비증가 — 두 결과가 다른 곳을 표본 추출(책당 30곳 이상)해 사람이 판정, 새 순서의 오교정 수 ≤ 기존 순서
  3. 쪽 경계 어절 끊김(쪽 끝 낱말이 다음 쪽 첫 낱말과 띄어진 채 남은 곳)·5자↑ 붙은 한글 덩어리 수가 기존 이하
  4. 책마다 비교 요약 파일이 생기고, 규칙별 바뀐 곳 수를 보여 준다
  5. 기존 테스트(`python -m pytest engine/tests`) 실패 0건

## 3. 범위
### 포함
- 정제 순서 재배치: 쪽 단위 맞춤법·띄어쓰기·오타 교정을 책 전체 정리(쪽 경계 잇기) 뒤로 이동
- 최종 검수 기록: 책마다 OCR 원문↔정제본 비교 요약(단계별 바뀐 곳 수·글자 수 변화) 파일 저장
- 기존 결과 재 OCR: 원본 PDF로 다시 처리(한자 인식 재처리와 한 번에 — 7번)
- 정제규칙서 §0(적용 순서) 갱신

### 제외
- 무역문서용 용어·수치 검증(첨부 문서 7단계) — 이 도구는 책 OCR 용
- 표를 Markdown 표로 바꾸기, 새 교정 규칙 추가
- Vision API·LLM 교정 경로 변경(현재 기본 미사용)

## 5. 제약 조건

## 6. 주요 프로세스
1. 쪽마다: 판독 → 깨진 글자 정리 → 쪽번호·잡음 제거 → 쪽 안 줄 잇기(맞춤법 교정 없음)
2. 책 전체: 머리글·부속물·쪽번호 제거 → 쪽 경계 문장 잇기
3. 책 전체: 맞춤법·어절 교정 → 사용자 오타 사전 → R-17 띄어쓰기
4. 비교 요약 저장, 의심 목록 저장
5. 기존 결과 재 OCR: 대상 책 원본 PDF로 1~4 실행 → 기존 결과 백업 후 교체

## 10. 1단계 비교 실측 결과 (2026-10-18) — 기준 불합격, 코드 수정 보류

표본: 3권 × 40쪽(31~70쪽), 같은 판독 원문을 지금 순서·새 순서로 정제. 두 결과가 다른 곳 **전수**(38곳)를 사람이 판정했다.

| 책 | 다른 곳 | 새 순서가 나음 | 새 순서가 나쁨 | 판정 불가(한자 음 잡음) | 한글 글자 수 변화 | EG |
|---|---|---|---|---|---|---|
| 대한민국CEO명언집 | 3 | 1 | 2 | 0 | 0 | E2✓ |
| 손자병법으로돌파한다2 | 16 | 1 | 7 | 8 | −4 | E2✓ |
| 장원_제갈량 | 19 | 2 | 16 | 1 | −18 (한 문장 사라짐) | E2✓ |
| **합계** | **38** | **4** | **25** | **9** | | |

- 성공 기준 1(글자 손실 없음) 불합격: 장원 표본(31~70쪽) 안 "수 있다면 천하를 거느리는 장수라 할 수 있다." 한 문장이 새 순서에서 빠졌다.
- 성공 기준 2(오교정 비증가) 불합격: 나빠진 곳 25 vs 나아진 곳 4. 대부분 띄어쓰기가 붙거나(`수는없다`·`않는자를`) 엉뚱하게 갈림(`자에게 는`·`언제 나`).
- 원인(확인 범위 4곳): 맞춤법 교정기가 줄이 이어진 글을 보면 다른 자리에 띄어쓰기를 넣어, 뒤따르는 R-17(5자↑ 붙은 덩어리만 띄움)의 대상에서 빠진다. 예: 지금 순서 `권위있는인물에의`(9자, R-17 이 `권위 있는 인물에의`로 띄움) ↔ 새 순서 `권위있는 인물에의`(4자, R-17 대상 아님).
- 쪽 경계에서 새 순서가 나아진 곳은 표본에서 0곳 ⟦E2✓⟧.
- 처리 시간: 책 전체 교정 40쪽당 0.1~1.1초 — 차이 없음.
- 재현: scratchpad `order/ocr_raw.py`(판독 원문) → `order/compare.py`(비교·다른 곳 추출).
