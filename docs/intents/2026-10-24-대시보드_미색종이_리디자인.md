# Intent: 대시보드 미색 종이 리디자인 — 카드 안 상자 걷어내기

## 1. 배경 및 문제
- 현재 문제: 대시보드(`engine/ocr_gradio.py`, Gradio 4탭) 카드 안에 버튼·목록·설명이 각각 글상자(테두리·배경 상자) 형태로 들어 있어 상자가 겹겹이 보이고 복잡하다. 배색도 청록(teal) 계열이라 사용자 스타일 가이드와 다르다.
  - 현재 카드 안 상자 요소(`_CSS` 52~197행): 선택지 항목마다 테두리(`.step-card fieldset label`), 안내 상자(`.note`·`.note.info/ok/warn/err`), 경고·이어하기 패널(`.warn-panel`·`.continue-panel`), 저장 현황 테두리 격자(`.stats`), 기록 표 테두리(`.rec-table`), 빈 결과 파일 칸 점선 상자(`.empty.large`)
- 영향받는 업무/사용자: OCR 도구를 쓰는 사용자 본인(비개발자). 처리·일괄·교정·엔진 설정·기록 확인 전 화면.

## 2. 목표
- 달성하려는 결과: 사용자 스타일 가이드 `Raw/Skills/data/reference/web_style_guide.html`(「미색 종이」 디자인 시스템)의 배색·형태로 대시보드를 다시 입히고, 카드 안은 상자 없는 심플한 모던 스타일로 정리한다.
- 성공 기준:
  1. 배색이 가이드 토큰과 같다 — 바탕 `--paper #f3efe7`, 카드 `--surface #fbf9f4`, 본문 `--ink #2f2b25`, 강조 남청 `--accent #436186`, 상태색 ok/warn/danger 저채도 값, 다크는 `#191714` 먹색 종이. 기존 청록(`#0f766e`) 0곳.
  2. 카드는 가이드 원칙 4대로 1px 옅은 선(`--line`) + 12px 둥근 모서리, 평소 그림자 없음.
  3. 카드 안에서 상자(테두리·배경 면)를 갖는 것은 **실행 메뉴 버튼**과 입력이 필요한 칸(텍스트 입력·파일 올리기·결과 텍스트 상자)뿐이다.
  4. 단순 목록·설명·안내 문구는 상자 없이 **작은 글자(본문보다 작게, 약 12.5~13px) 텍스트**로 표시한다. 경고·오류는 상태색 글자로 구분한다.
  5. 기능 변화 없음 — 기존 점검 `python -m pytest engine/tests` 통과, 4탭 버튼·이벤트 동작 그대로.
  6. 4탭(라이트·다크) 바꾸기 전·후 화면 캡처로 1~4·7·8을 확인한다.
  7. (추가 2026-10-24) 탭 안 글자 크기를 단계로 표준화한다 — 카드 제목 15px · 본문/선택지 13px · 목록(파일·대기열·기록)·설명·안내 12px · 진행 기록 글상자 12px. 이 밖의 임의 크기 없음.
  8. (추가 2026-10-24) 버튼을 지금보다 작게(높이 약 30px, 글자 12.5px) 하고 글자 폭만큼만 차지하게 해, 한 줄에 놓인 버튼들이 세로로 쌓이지 않고 가로로 나열된다(카드 폭 320px 이상에서).

## 3. 범위
### 포함
- `engine/ocr_gradio.py` 의 `_CSS`·`_THEME` 교체(가이드 토큰으로)
- 카드 안 상자 요소를 텍스트형으로 변경: 안내 상자, 경고·이어하기 패널, 저장 현황 숫자, 선택지(라디오·체크박스) 항목 테두리, 기록 표 바깥 테두리
- 머리말(제목·상태 칩)·탭 바·진행바의 배색을 가이드에 맞춤
- 위 변경에 필요한 최소한의 HTML 클래스 조정(안내 문구를 만드는 함수의 `class` 값 등)
### 제외
- 탭 구성·순서, 버튼 종류·배치, 이벤트 연결, 처리 로직
- 가이드의 「홈페이지 구성」(고정 헤더·왼쪽 메뉴·짙은 배너·숫자 카드 4개) 재배치 — 현재 머리말+4탭 구조 유지
- 종이 결(노이즈) 같은 질감 이미지 — 가이드에 정의가 없음(가이드의 「종이」는 배색 이름)

## 5. 제약 조건
- Gradio 기본 구성요소의 내부 클래스에 CSS로 덮어쓰는 방식 — 새 패키지 추가 없음.
- 서체: 가이드는 Pretendard. 현재도 Pretendard 우선이므로 유지(설치 안 된 PC는 맑은 고딕으로 대체).
- 보호 경로(`config/**` 등)는 건드리지 않는다.
- 화면 시험은 서버를 하나만 띄우고, 멈추면 시간제한 독립 스크립트로 확인한다(lessons 2026-09-27).

## 6. 주요 프로세스
1. 바꾸기 전 4탭 캡처(라이트·다크)
2. `_CSS` 토큰을 가이드 값으로 교체, `_THEME` 색 지정 교체
3. 카드 안 상자 요소를 텍스트형·작은 글자로 변경, 실행 버튼만 상자 유지
4. `pytest` 실행, 대시보드 재시작 후 4탭 캡처 → 성공 기준 1~4 대조표 작성
5. 사용자 확인

## 7. 예외 및 리스크
| 상황 | 처리 방향 |
|---|---|
| 경고·오류가 글자만으로는 눈에 덜 띔 | 상태색 글자 + 굵기로 구분. 확인 후 부족하면 왼쪽 색 줄 추가 여부를 묻는다 |
| 선택지 상자를 없애면 클릭 영역이 좁아 보임 | 테두리만 없애고 줄 높이·여백은 유지, 선택된 항목은 남청 글자로 표시 |
| 긴 파일 목록(② 탭)이 테두리 없이 경계가 흐려짐 | 목록 위·아래 1px 구분선만 둔다(스크롤 영역 유지) |
| Gradio 내부 클래스가 CSS를 이김 | `!important` 범위를 `.step-card` 안으로 한정 |
