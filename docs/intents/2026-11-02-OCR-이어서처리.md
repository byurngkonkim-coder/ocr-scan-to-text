## 1. 배경 및 문제
- 현재 문제: 「분석의힘_삼일PWC…」(277쪽) 전체 처리가 261쪽 저장 후 21:46부터 멈춤. 서버 재시작 외 방법이 없고, 다시 돌리면 277쪽을 처음부터 Gemini로 다시 읽어 요금·시간이 두 번 든다.
  - 읽은 쪽은 `02_결과/{원본명}_OCR중.txt` 에 쪽마다 쌓이지만(`engine/ocr_gradio.py:1766`), 다음 실행은 이를 읽지 않고 시각 붙은 새 체크포인트를 만든다(`:306-320`).
  - 쪽 결과를 시간 제한 없이 기다린다(`:1763` `fut.result()`). 멈춘 정확한 지점은 스택을 못 떠서 확인하지 못했다 ⟦E3: 정황 추론 — CPU 0·외부 연결 없음⟧.
- 영향받는 업무/사용자: 스캔 서적을 ① 처리하기·② 일괄 처리로 돌리는 사용자(PM 본인). 큰 책일수록 손실이 크다.

## 2. 목표
- 달성하려는 결과: 끊긴 책을 다시 처리하면 저장된 쪽은 건너뛰고 남은 쪽만 읽어, 기존과 같은 최종 결과 파일을 만든다. 한 쪽이 응답 없이 멈춰도 전체가 서지 않는다.
- 성공 기준:
  1. 오늘 백업한 261쪽 체크포인트로 「분석의힘」을 다시 처리하면 OCR 호출이 **약 17쪽**(마지막 저장쪽 재확인 1쪽 + 262~277쪽)만 일어난다 — 진행 기록에 「261쪽 복원, 261쪽부터 이어서」 표시.
  2. 최종 결과 파일이 1~277쪽 본문을 담는다(쪽 누락 0건 — 쪽 머리줄 수로 측정, 복원 쪽 본문이 체크포인트와 일치).
  3. ① 처리하기와 ② 일괄 처리 양쪽에서 같은 동작.
  4. 한 쪽이 제한 시간을 넘기면 그 쪽은 「검토 필요(시간 초과)」로 비워 두고 다음 쪽으로 진행한다 — 테스트로 재현.
  5. `python -m pytest engine/tests` 전체 통과.

## 3. 범위
### 포함
- 자동 이어 하기: 같은 원본명의 `_OCR중*.txt` 가 있으면 묻지 않고 복원 → 남은 쪽 처리. 체크포인트가 여러 개면 쪽이 가장 많은 것을 쓴다.
- 마지막 복원 쪽은 기록 도중 끊겼을 수 있으므로 버리고 다시 읽는다(1쪽 비용).
- 정상 완료 시 이번 실행 체크포인트와 함께 **복원에 쓴 체크포인트도 삭제**(기존 「다 읽고 확정됐을 때만 지운다」 규칙 유지).
- 쪽당 대기 시간 제한(`engine/config.json` 설정값, 기본값은 8번 질문 참고).
- ① 처리하기·② 일괄 처리 둘 다 — 둘 다 같은 `_run_ocr` 를 지나므로 한 곳 수정으로 덮인다(`batch_runner.py:197` → `process_full` → `_run_ocr`).
### 제외
- 「이어서 / 처음부터」 선택 화면이나 별도 버튼(사용자 선택: 자동).
- 문장 정제 단계(`_정제중`) 이어 하기 — 정제는 로컬 규칙이라 다시 해도 비용 0.
- 디지털 PDF·텍스트 파일 경로(OCR 없음).
- 미리보기 → 「계속」 경로(이미 이미지 캐시로 이어 함).

## 5. 제약 조건
- 체크포인트에는 **본문만** 있다 — 복원 쪽의 엔진·신뢰도·검토 필요 표시·표(table) 정보는 없다. 복원 쪽은 엔진 「복원」으로 기록된다.
- 외부 패키지 추가 없음.
- 원본·기존 체크포인트를 덮어쓰지 않는다(복원은 읽기만).

## 6. 주요 프로세스
1. 전체 처리 시작 → 스캔 PDF로 판정되면 같은 원본명의 `_OCR중*.txt` 를 찾는다.
2. 있으면 `[페이지 N]` 단위로 나눠 마지막 쪽을 뺀 나머지를 결과에 넣고, 진행 기록에 복원 쪽수를 남긴다.
3. 남은 쪽부터 렌더·OCR(새 체크포인트에는 복원 쪽도 먼저 옮겨 적어, 또 끊겨도 한 파일에 다 남게 한다).
4. 쪽마다 제한 시간 안에 결과가 없으면 「검토 필요(시간 초과)」로 비우고 다음 쪽.
5. 이후 정제·저장·기록은 기존과 동일. 확정되면 쓴 체크포인트들을 지운다.

| 시간 초과된 쪽의 작업 스레드 | 취소 불가(파이썬 스레드) — 결과는 버리고 진행, 응답이 늦게 와도 무시 |
