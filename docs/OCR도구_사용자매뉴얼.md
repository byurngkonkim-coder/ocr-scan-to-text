# OCR 스캔파일 텍스트추출 도구 — 사용자 매뉴얼

> [!NOTE]
> **핵심 3줄 요약**
> 1. **`START_OCR.bat` 더블클릭** → 열린 화면에서 **1 파일 선택 → 2 처리 방식 → 3 실행 → 4 결과** 순서로 진행합니다.
> 2. **API 키는 화면에 입력하지 않습니다.** Windows 환경변수(`GEMINI_API_KEY`)에 한 번 등록하면 자동으로 쓰입니다.
> 3. 결과는 **`02_결과`** 폴더에 저장됩니다. 문제가 생기면 `engine\ocr_server.log` 를 확인하세요.
> 4. **기본(비용 우선)은 거의 무료**입니다. 유료는 스캔본의 Vision 읽기(정확도 우선·흐린 쪽 보완·검토 필요 쪽 다시 읽기)뿐 — 소스별 선택은 **8. 입력 소스별 활용 기준**.

---

## 1. 이 도구는 무엇인가요?

스캔된 **PDF·이미지(PNG/JPG/TIFF)** 에서 글자를 뽑아 **텍스트 파일(.txt/.md)** 로 저장하는 도구입니다.

- **디지털 PDF**(글자 정보가 들어 있는 PDF)는 OCR 없이 **무료로 바로** 추출합니다. 파일을 올리면 화면이 자동으로 알려 줍니다.
- **스캔 PDF·이미지**는 OCR 엔진 두 가지를 함께 씁니다.
  - **RapidOCR 한글 v5** — 이 PC에서 도는 **무료** 엔진 (별도 프로그램 설치 없음)
    - 한글 모델이 못 읽는 **한자**는 같이 들어 있는 한자 모델로 다시 읽어 넣습니다(예: `축도(縮圖)`, `무경칠서武經七書`). 확실하지 않은 한자는 넣지 않고 비워 두므로 빈 괄호 `()` 가 일부 남을 수 있습니다.
  - **Vision 엔진** — 레이아웃을 이해하는 **고정확** 엔진. 화면에서 셋 중 하나를 고릅니다.
    **Google Gemini**(기본·가장 빠름) / **Anthropic Claude** / **로컬 Ollama**(무료·느림)
- 한국어·영어·혼합 문서를 지원합니다.

## 2. 폴더 구성

```
01_OCR_스캔파일텍스트추출프로그램\
├─ START_OCR.bat            ← 실행 (매번)
├─ STOP_OCR.bat             ← 종료
├─ OCR_대시보드_열기.url     ← 켜져 있는 화면을 다시 열 때
├─ 01_입력\                 ← 처리할 PDF·이미지를 넣어 두는 곳 (④ 일괄 처리 목록)
├─ 02_결과\                 ← 완성된 텍스트가 저장되는 곳
├─ docs\                    ← 이 매뉴얼 등
└─ engine\                  ← 프로그램 본체 (설치: engine\install.bat, 건드리지 않아도 됩니다)
```

## 3. 설치 (처음 한 번만)

### 3-1. 사전 프로그램

| 프로그램 | 용도 | 비고 |
|---|---|---|
| **Python 3.10+** | 도구 실행 | [python.org](https://www.python.org) — 설치 시 **"Add Python to PATH" 체크** |
| **Poppler** (PDF만) | PDF→이미지 변환 | [poppler-windows](https://github.com/oschwartz10612/poppler-windows/releases) → `C:\poppler\Library\bin`. 이미지만 쓰면 불필요 |
| **Ollama** (선택) | 로컬 Vision 엔진 | 로컬 Ollama 엔진을 쓸 때만. [ollama.com](https://ollama.com) |

### 3-2. 프로그램 설치

**`engine\install.bat` 을 더블클릭**합니다. 전용 가상환경(`engine\venv`)을 만들고 OCR 엔진(RapidOCR)을 포함한 필요한 패키지를 설치합니다.

> `START_OCR.bat` 은 이 전용 환경의 Python을 자동으로 씁니다. PC에 Python이 여러 개 있어도 섞이지 않습니다.

## 4. API 키 등록 (환경변수)

**키는 화면에 입력하지 않습니다.** Windows 환경변수에 한 번 등록하면 프로그램이 시작할 때 자동으로 읽습니다.
키가 없어도 RapidOCR과 내장 문장 정제로 동작합니다. **정확도 우선**과 흐린 쪽 Vision 보완, 검토 필요 쪽 다시 읽기를 쓰려면 Gemini 키가 필요합니다.

1. **키 발급** — [Google AI Studio](https://aistudio.google.com/app/apikey) 에서 API 키를 만듭니다.
2. Windows 검색창에 **환경 변수** 입력 → **계정의 환경 변수 편집** 을 엽니다.
3. **사용자 변수 → 새로 만들기** → 변수 이름 **`GEMINI_API_KEY`**, 값에 키를 붙여넣고 확인합니다.
4. 열려 있던 START_OCR 창을 닫고 **`START_OCR.bat` 을 다시 실행**합니다. (환경변수는 시작할 때만 읽힙니다)

| 엔진 | 변수 이름 | 키 발급처 |
|---|---|---|
| Google Gemini | `GEMINI_API_KEY` (또는 `GOOGLE_API_KEY`) | [Google AI Studio](https://aistudio.google.com/app/apikey) |
| Anthropic Claude | `ANTHROPIC_API_KEY` | [Anthropic 콘솔](https://console.anthropic.com/settings/keys) |
| 로컬 Ollama | 필요 없음 | — |

- 등록이 됐는지는 화면 오른쪽 위 상태 표시(**엔진 … · 키 연결됨**)와 **② 엔진 · API 키** 탭에서 확인합니다. 화면에는 **어느 변수에서 읽었는지만** 보이고 키 값은 보이지 않습니다.
- 🔒 키는 채팅·메신저·문서에 붙여넣지 마세요. 노출되면 발급처에서 폐기 후 재발급하세요.

## 5. 실행과 종료

1. 맨 위 폴더의 **`START_OCR.bat` 더블클릭**
2. 검은 콘솔창이 뜨고 잠시 후(처음 약 10~15초) **브라우저가 자동으로 열립니다** → `http://localhost:7860`
3. 브라우저 탭을 닫았다면 **`OCR_대시보드_열기.url`** 로 다시 엽니다. (프로그램이 켜져 있을 때만 열립니다)
4. **종료**: 검은 콘솔창에서 `Enter` 를 누르거나 창을 닫습니다.

> 화면은 1920×1080 모니터에서 스크롤 없이 한눈에 보이도록 맞춰져 있습니다.

## 6. 화면 사용법

화면 맨 위에는 **현재 엔진·키 연결 상태**와 **문장 정제 사용 가능 여부**가 항상 표시됩니다.

### ① 처리하기 — 왼쪽에서 오른쪽으로 1 → 4

| 단계 | 할 일 |
|---|---|
| **1 파일 선택** | PDF·이미지를 끌어다 놓거나 클릭해 올립니다. 올리면 **디지털 PDF인지 스캔본인지**, 쪽수가 바로 표시됩니다. |
| **2 처리 방식** | **읽는 방식**과 **문장 정제**를 고릅니다. 디지털 PDF는 OCR을 하지 않으므로 읽는 방식은 쓰이지 않습니다. |
| **3 실행** | 처음이면 **앞 3쪽 미리보기**로 품질을 확인하고, 괜찮으면 **전체 처리**. 디지털 PDF는 바로 전체 처리해도 됩니다. |
| **4 결과** | 진행률·진행 기록·본문 미리보기가 나타나고, 끝나면 **결과 파일**을 내려받을 수 있습니다. **결과 폴더 열기** 로 `02_결과` 를 바로 엽니다. |

**2 처리 방식 자세히**

- **읽는 방식**
  - **정확도 우선** — Vision 엔진이 먼저 읽고, 실패하면 RapidOCR. 최고 품질, 쪽마다 API 요금.
  - **비용 우선** (기본) — RapidOCR(무료)가 모든 쪽을 먼저 읽고, **RapidOCR 신뢰도가 85% 미만이거나 자모가 분리된 쪽만** Vision 엔진으로 다시 읽습니다. 이미지가 흐려 보여도 RapidOCR이 잘 읽으면 유료로 보내지 않습니다. Vision은 **문서당 쪽수의 10%(최소 3쪽)** 까지만 쓰고, 나머지는 `검토 필요` 로 남깁니다.
- **문장 정제** (기본 꺼짐) — OCR 후 문서 전체를 한 번 더 손봐 **바로 읽을 수 있는 깨끗한 본문**으로 저장합니다. 소스와 읽는 방식에 상관없이 **내장 정제규칙(무료·즉시, API 호출 없음)** 으로 합니다.
  - 없애 주는 것: `[페이지 N]` 표시·구분선·단독 자모, 쪽번호·반복 머리말
  - 고쳐 주는 것: 쪽이 넘어가며 잘린 단어 이어붙이기, 단락 복원, 띄어쓰기·맞춤법(한글 교정기의 사전 범위)
  - **전체 처리에만** 적용됩니다(미리보기 제외).
- **표지·판권·차례 같은 앞뒤 부속물도 삭제** (기본 꺼짐) — 문장 정제가 켜져 있을 때만 동작하며, **차례와 판권(간기)** 을 규칙으로 지웁니다. 표제지·헌사는 남을 수 있습니다.

**소스별 자동 처리** — 프로그램이 파일 종류를 보고 정합니다. 사용자가 고른 읽는 방식보다 이 규칙이 우선합니다.

| 소스 | 자동 처리 |
|---|---|
| 디지털 PDF | OCR 없이 내장 글자 추출. 정확도 우선을 골라도 유료 호출 없음 |
| txt | 그대로 읽음. 유료 호출 없음 |
| 스캔 PDF·이미지 | 고른 읽는 방식대로 (④ 일괄 처리는 비용 우선 고정) |
- **고급 설정** (보통은 그대로) — OCR 언어, 저장 형식(txt/md), 이미지 전처리·자동 재인식·그림 감지 끄기, 위아래 여백 잘라내기, 쪽마다 추가 교정(L3 · Claude Haiku, `ANTHROPIC_API_KEY` 필요).

**미리보기를 했을 때** — 결과 칸에 **나머지 쪽 계속 처리**(다시 변환하지 않고 이어서 처리)와 **미리보기까지만 저장** 버튼이 나타납니다.

**`검토 필요` 쪽이 남았을 때** — 스캔본 전체 처리가 끝나면 결과 칸에 **"검토 필요 N쪽만 Google Gemini으로 다시 읽기 (약 $X)"** 버튼이 나타납니다. 누르면 그 쪽만 Vision 엔진으로 다시 읽어 교체하고, 결과 파일을 `02_결과` 에 새로 저장합니다. 문서 전체를 정확도 우선으로 다시 돌리는 것보다 훨씬 저렴합니다. Vision 키가 없거나 결제 오류로 멈춘 상태면 버튼이 나타나지 않습니다.

| **API 키 적용 방법** | 키 연결 상태(어느 환경변수에서 읽었는지)와 등록 방법 안내. Ollama를 고르면 앱 실행·모델 설치 안내가 나옵니다. **연결 상태 다시 확인** 으로 새로 확인합니다. |

| **기본 설정** (접힘) | 기본 언어·저장 형식·해상도(DPI)·여백 설정. 다음 실행부터 적용됩니다. |

### ③ 처리 기록

- **저장 현황** — 처리 기록 수, 보관된 결과 수, 사용 용량과 지금까지의 처리 목록
- **기록 선택** — 목록에서 기록을 골라 **결과 파일·원본 파일 다시 받기**, 또는 **선택한 기록 삭제**
- **보관 설정 · 전체 초기화** (접힘) — 올린 원본도 함께 보관할지, 처리 기록 전체 삭제
- 방금 처리한 기록이 안 보이면 **새로고침** 을 누르세요.

### ④ 일괄 처리 — 결과 파일 다시 교정 · 의심 목록 (2026-10-18 추가)

- **결과 파일 다시 교정** — `02_결과` 의 txt 를 골라 **선택 파일 다시 교정 ▶**. 지금의 자동 교정(오타 사전·내가 등록한 오타·붙은 낱말 띄어쓰기)을 다시 적용하고 같은 이름으로 덮어씁니다. 원본은 `_백업\재교정_날짜_시각\` 에 보관됩니다. 바뀐 게 없으면 파일을 건드리지 않습니다. 여러 번 눌러도 결과는 같습니다.
- **의심 목록** — 자동으로 고치지 않은 '틀렸을 수 있는 말'입니다. 본문은 바뀌지 않습니다. 일괄 처리나 다시 교정을 하면 책마다 `02_결과\_의심목록\책이름.tsv` 로 생깁니다.
  1. 책을 고르면 표가 나옵니다(틀린 말 · 고칠 말 · 바뀔 곳 · 문맥).
  2. 맞는 것만 **등록** 칸에 체크합니다. 제안이 틀렸으면(예: `흘륨→흙륨`) **고칠 말** 칸을 직접 고칩니다(`훌륭`).
  3. **선택 항목 사전 등록** → `engine\user_typos.tsv` 에 저장되고, 다음 처리와 다시 교정부터 자동으로 고칩니다.
  - 1글자 항목, 고칠 말 안에 틀린 말이 들어 있는 항목, 이미 등록한 항목과 겹치는 항목은 거부됩니다(다른 낱말을 망가뜨리지 않게).
- 제안은 로컬 형태소 분석기(Kiwi)가 냅니다. 실측에서 맞는 제안은 4개 중 1개꼴이라 **체크 전에 문맥을 꼭 보세요**.
- **검수기록** — 「문장 정제」를 켜고 처리한 책마다 `02_결과\_검수기록\결과파일이름.txt` 가 생깁니다. 판독 원문 → 쪽 교정 후 → 최종 정제본의 글자 수(한글·한자·숫자·영문·어절)와 정제 보고(띄어쓰기 몇 곳, 지운 머리글 쪽 등)가 들어 있습니다. 최종 글자 수가 원문보다 크게 줄었으면 본문이 빠졌을 수 있으니 원문과 대조하세요. ④ 처리 상세에도 위치가 나옵니다.

## 7. 결과물

- **저장 위치**: **`02_결과`** 폴더 (`처리일시_파일이름.txt`). 화면의 **결과 파일** 로 내려받을 수도 있습니다.
- **내부 보관**: 같은 결과의 사본과 처리 이력이 `engine\storage` 에 남아 **③ 처리 기록** 에서 다시 받을 수 있습니다. 문장 정제를 했다면 정제 전 원문(`…_원문.txt`)도 이곳에 함께 보관됩니다.
- **문장 정제 켜짐**: 쪽 표시·쪽번호·머리말 없는 **깨끗한 본문**(단락은 빈 줄로 구분).
- **문장 정제 꺼짐**: 쪽마다 `[페이지 N]` 구분이 들어간 OCR 원문. 품질이 낮은 쪽은 `검토 필요` 로 표시됩니다.
- 긴 책을 정제하는 중 문제가 생겨도, 그때까지 정제된 부분은 `02_결과\…_정제중.txt` 로 남습니다.

## 8. 입력 소스별 활용 기준 (비용·품질)

> 2026-10-15 비용 사고 뒤 정한 운영 기준입니다. 디지털 PDF 311개를 문장 정제(Gemini)로 돌려 크레딧이 바닥났고,
> 누적 요금의 약 94%가 OCR이 아니라 **문장 정제**에서 나왔습니다. 정제는 본문 전체를 다시 써서 돌려받기 때문에
> 쪽당 요금이 Vision OCR보다 약 4배 비쌉니다(추정: 정제 약 $0.004/쪽, Vision 약 $0.0011/쪽).

### 8-1. 소스별 추천

| 입력 소스 | 읽는 방식 | 문장 정제 | 예상 요금 | 품질 |
|---|---|---|---|---|
| **디지털 PDF** (1단계에 "디지털 PDF"로 표시) | 자동(OCR 안 함, 모드 무시) | 필요하면 켬 → 내장 규칙 | **0원** | 원문 글자 그대로 |
| **txt** | 자동(모드 무시) | 필요하면 켬 → 내장 규칙 | **0원** | 입력 그대로 |
| **선명한 스캔 PDF·이미지** | **비용 우선** | 필요하면 켬 → 내장 규칙 | 거의 0원 (흐린 쪽만, 문서당 최대 10%) | 양호 |
| **흐리거나 중요한 스캔** | ① 비용 우선 → ② **검토 필요 쪽만 다시 읽기** 버튼 → ③ 그래도 부족하면 정확도 우선으로 다시 | 내장 규칙 | 다시 읽기 쪽당 약 $0.0011, 정확도 우선 300쪽 약 $0.3 (추정) | 높음 |
| **인터넷·키 없음** | **비용 우선** (키 없이) | 내장 규칙 | 0원 | 양호 |

### 8-2. 지킬 것

- 디지털 PDF·txt 는 정확도 우선을 골라도 프로그램이 자동으로 무료 경로로 처리합니다.
- **④ 일괄 처리는 비용 우선으로 고정**돼 있습니다(화면에서 바꿀 수 없음). 정확도 우선은 **한 권씩 ① 처리하기**에서만 씁니다.
- 일괄 처리가 끝나면 **③ 처리 기록**에서 Vision 쪽 수가 많거나 `검토 필요` 가 많은 문서만 골라 ① 탭에서 전체 처리한 뒤 **검토 필요 쪽만 다시 읽기**를 씁니다.
- **쪽마다 추가 교정(L3 · Claude Haiku)** 은 꺼 둡니다. 엔진과 별도로 쪽마다 요금이 듭니다.
- 소스가 섞인 폴더도 기본값이면 안전합니다. 다만 흐린 스캔은 문서당 Vision 상한(10%)에 걸려 `검토 필요` 로 남을 수 있으니 위 방법으로 다시 처리합니다.

### 8-3. 결제 계정 안전장치 (프로그램 밖 — 직접 확인)

- Google AI Studio 결제는 **선불 크레딧**으로 두고 **자동 충전은 끕니다.** 크레딧이 바닥나면 호출이 멈출 뿐 추가 청구가 없습니다. 자동 충전을 켜면 이 상한이 사라집니다.
- 프로그램은 결제·인증 오류(크레딧 소진 등)를 한 번 받으면 그 실행이 끝날 때까지 Gemini 호출을 멈춥니다. 충전한 뒤에는 **START_OCR 를 다시 실행**하세요.
- 디지털 PDF·txt 와 문장 정제는 이제 유료 호출을 하지 않으므로, 충전 후 남은 위험은 스캔본을 정확도 우선으로 대량 처리하는 경우뿐입니다(④ 일괄은 비용 우선 고정).

## 9. 문제 해결 (FAQ)

| 증상 | 원인 / 해결 |
|---|---|
| **콘솔창이 열렸다 바로 닫혀요** | 설치가 안 된 상태입니다. **`engine\install.bat`** 을 한 번 실행하세요. |
| **브라우저가 안 열려요** | `engine\ocr_server.log` 를 열어 오류를 확인하세요. 대개 ① 7860 포트를 다른 프로그램이 사용 중 ② 패키지 누락(`engine\install.bat` 재실행) |
| **브라우저 탭을 닫았어요** | 프로그램이 켜져 있으면 **`OCR_대시보드_열기.url`** 로 다시 엽니다. 이미 켜져 있을 때 `START_OCR.bat` 을 다시 눌러도 같은 화면이 열립니다. |
| **"Python이 설치되어 있지 않습니다"** | Python 미설치 또는 PATH 누락 → 재설치 시 "Add to PATH" 체크 |
| **PDF 처리 실패** | Poppler 미설치 → `C:\poppler\Library\bin` 설치 |
| **상태 표시가 "API 키 없음"** | 환경변수 등록 후 **START_OCR 창을 닫고 다시 실행**했는지 확인하세요. 변수 이름 오타(`GEMINI_API_KEY`)도 확인합니다. |
| **"키가 config.json 에 평문 저장됨" 경고** | 예전 방식으로 저장된 키가 남아 있습니다. 환경변수로 등록한 뒤 `engine\config.json` 의 키 값을 비우세요. |
| **"등록된 키의 형식이 올바르지 않습니다"** | 같은 키가 두 번 붙여넣어졌을 수 있습니다. 환경변수 값을 다시 확인하세요. |
| **문장 정제를 켰는데 Gemini 로 정제되지 않아요** | 정상입니다. 문장 정제는 비용 사고 뒤 모든 소스에서 내장 규칙으로만 합니다(2026-10-15). |
| **④ 탭에서 정확도 우선을 고를 수 없어요** | 정상입니다. 대량 과금을 막으려고 일괄 처리는 비용 우선으로 고정했습니다. ① 탭에서 한 권씩 쓰세요. |
| **"Vision 폴백 실패 — 검토 필요" 가 많아요** | 대개 Gemini **크레딧 소진**(402)이나 키 문제입니다. AI Studio에서 잔액을 확인하고 충전한 뒤 START_OCR 를 다시 실행하세요. 그 전까지는 RapidOCR 결과로 저장됩니다. |
| **"문서당 Vision 상한 도달(비용 보호)" 표시** | 흐린 쪽이 문서의 10%를 넘었습니다. 결과 칸의 **검토 필요 쪽만 다시 읽기** 버튼을 쓰거나, 이 문서만 ① 탭에서 정확도 우선으로 다시 처리하세요(8-2 참조). |
| **요금이 예상보다 많이 나왔어요** | ② 탭 **API 사용량**에서 정제(llm)와 Vision 중 어느 쪽인지 확인하세요. 2026-10-15 이전 기록이면 대부분 디지털 PDF·대량 문서를 Gemini 정제로 돌린 경우입니다. 지금은 정제(llm)가 늘지 않아야 정상입니다. |
| **로컬 Ollama "미연결"** | Ollama 앱을 실행하고 모델을 설치(`ollama pull qwen3-vl:4b-instruct`)한 뒤 **연결 상태 다시 확인** |
| **한글 정확도가 낮음** | 그 문서만 Gemini 키를 등록하고 **정확도 우선** 으로 다시 처리 (일괄 처리 금지 — 8-2 참조) |

> 그래도 안 되면 `engine\ocr_server.log` 전체 내용을 첨부해 문의하세요. (실패 원인이 기록됩니다)
